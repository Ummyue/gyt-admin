# 02.01 项目准入 · 需求规格说明（原型反向生成）

> **文档性质**：由已实现原型页面反向推导的需求规格，用于核对原型实现与业务口径是否一致。
> **生成方式**：逐页读取 `project-list` / `project-apply` / `project-detail` 三个原型的实际结构与交互，再与既有需求口径比对。
> **生成时间**：2026-10-23
> **对应既有规格**：`docs-v2/02.01-项目管理.md`（业务方 2026-10-21 裁决后口径）

## 0. 本文说明

### 0.1 溯源约定

本文每条需求都带依据标记，用于区分规则来自哪里、可靠度多高：

| 标记 | 含义 | 验收时如何对待 |
|---|---|---|
| **【原型】** | 原型页面已实现，规则可点击核验 | 直接对照页面验证 |
| **【文档】** | 既有需求口径已明确（业务方已裁决），原型未实现或本次未核验 | 以文档为准，原型需补齐 |
| **【推导】** | 从原型界面结构反推出的行为约束，规则未单独成文 | 需业务方确认是否成立 |
| **【差异】** | 原型实现与文档口径不一致 | **不可直接判定，必须业务方裁决** |

> 需求块本身只写「用户做什么 → 系统做什么 → 如何验收」，依据写在块尾；本节不重复各条规则。

反向生成的主要产出。以下 **17 项**是**原型实际实现**（含审批引擎模板）与**既有文档口径**对不上的地方，按影响程度排序：

| # | 差异点 | 原型实际 | 既有文档口径 | 影响 |

| **D1** | **附件大小上限** | **10MB**。列表页「上传客户准入报告」弹窗提示「支持上传 pdf / jpeg / jpg / png 格式文件，单个文件不超过 10MB」并有前端校验；关联企业弹窗材料提示「单个文件 ≤ 10MB」 | 裁决 D8 明确**单个附件 ≤ 100MB** | 🔴 **同一功能两个阈值并存**，且原型值小于文档值 10 倍。上线前必须统一，否则按文档做会被原型拒绝 |

## 1. 目标与范围

### 1.1 业务目标

项目准入是平台的业务起点与客户准入入口：业务人员发起立项申请 → 关联上下游企业 → 逐企业做风险报告 → 串行审批 → 准入完成并沉淀客户档案。

### 1.2 本期范围

- 项目列表（状态页签、筛选、导出、行内操作）
- 新增立项申请 5 步向导（项目基本信息 → 企业尽调报告 → 贸易风控合规报告 → 审批详情 → 准入完成）
- 项目详情（尽调与合规报告、审批进度、操作按钮）
- 审批链运行（串行审批、催办、加签、撤回、驳回）
- 项目完成后的跨模块触发（客户沉淀、合同创建）

### 1.3 不在本期范围

- 表结构与字段级 DDL（既有裁决已明确不进 PRD）
- 并发控制的技术实现方案
- 移动端 / 非 WEB 终端
- 风险运营报表、风控规则配置（已由业务方裁决移出交付范围）

## 2. 角色与关键概念

| 角色 | 在本模块中的职责 |
|---|---|
| 业务人员 | 发起立项、填报项目信息、关联企业、上传材料、提交审批、撤回 |
| 业务部负责人 | 审批节点 2（一级业务部） |
| 风控部 | 审批节点 3a |
| 财务部 | 审批节点 3b（风控部通过后自动流转） |
| 总经理 | 审批节点 4 |
| 系统 | 推送审批消息、SLA 超时催办、客户沉淀 |

**关键概念**

- **关联企业**：与项目关联的上下游客户、第三方物流、第三方仓储，共 4 种关联类型
- **企业风险扫描结果**：天眼查 + 平台自建黑灰名单/假国央企库产出的 6 类风险报告
- **贸易风控合规报告**：针对关联企业之间的贸易关系出具的合规校验结论
- **双编号轨**：业务立项编号 `LX{YYYYMMDD}{3位}`（给业务看）+ 系统项目编号（给系统关联用）

## 3. 状态与枚举（共享规则）

项目流程状态共 6 个，与状态机完全一致；列表页在此之外额外提供聚合的「全部」页签。

| 枚举值 | 中文 | 触发条件 | 下一状态 |
|---|---|---|---|
| `pending_submit` | 待提交 | 创建立项申请 / 驳回后重新提交 / 申请人撤回 | `approving` / `voided` |
| `approving` | 审批中 | 业务人员提交 | `executing` / `rejected` / `voided` / `pending_submit` |
| `executing` | 执行中 | 审批链全部节点通过 | `finished` |
| `finished` | 已完结 | 业务完结或主动终止 | 终态，归档 |
| `rejected` | 驳回 | 任一节点驳回 | `pending_submit` |
| `voided` | 已作废 | 审批中主动作废 | 终态，归档 |

> 审批链为**串行**：节点 1 提交 → 节点 2 一级业务部 → 节点 3a 风控部 → 节点 3b 财务部 → 节点 4 总经理 → 节点 5 准入完成。任一节点驳回即终止，转 `rejected`，申请人可编辑后重新提交。**无并行会签分支**。
>
> ⚠️ **该口径与原型引擎实现不一致**：引擎 `standard` 模板的节点 3 为 `parallel_all` 并行会签（风控 + 财务两名审批人），且节点 4 带「金额 > 100 万」触发条件。详见 §0.2 D2 / D3 / D4。

**关联类型**：`upstream` 上游企业 / `downstream` 下游企业 / `third_party_logistics` 第三方物流 / `third_party_warehouse` 第三方仓储

**业务类型**：`inventory` 存货业务 / `prepayment` 预付业务 / `credit_period` 账期业务 / `trade` 购销业务 / `agency_business` 总代业务（原型暂缺末项，见差异 D2）

**货物品类**：淀粉 / 糖粉 / 谷物（全平台统一）

验收：节点停留超过阈值后实时活动区出现自动催办记录，且催办卡显示「已 2 小时未处理」；「已耗时」文案出现「建议催办或 @该审批人加速处理」；点击「立即催办」产生一条催办记录；催办次数达到 3 次后不再自动催办并触发升级。

依据：【原型】申请页与详情页均实际渲染「立即催办」按钮；【文档】既有规格 §4.1「SLA 阈值 2 小时 / 催办最多 3 次后升级」、§2.5 审批异常表、§3.3「SLA 超时告警态」；【差异】界面按 2 小时判定超时，但引擎 `standard` 模板各节点 `afterHours` 为 24 / 48 / 24，两套阈值并存（D5）。
