## 1. 业务定位

**保证金登记** 是保证金池的入口操作——业务人员在合同签订后（或追加保证金时）发起**首次缴存 / 累加缴存**，对应保证金池里的"已付保证金金额"一笔正向登记。

| 维度 | 保证金登记（本页） | 保证金调整（margin-adjust） |
|------|---------------------|-----------------------------|
| 业务语义 | 缴存保证金（资金流入） | 调整保证金（资金转移/冲抵/退还） |
| 触发场景 | 合同签订后首次缴存 / 追保 | 冲抵最后一笔货款 / 转移至另外一笔业务 / 退款 |
| 对保证金池影响 | `paid += 本次登记金额` | `paid -= 调整金额` |
| 审批流 | 通常不需要走 OA（**业务流轻**，在页面提示线下打款后系统登记） | 必须走 OA + NC 审核 |

### 1.1 入口

| 入口 | URL | 说明 |
|------|------|------|
| 保证金池抽屉"登记保证金"按钮（v1.7.99.337）| `./margin-register.html?contractNo={合同编号}` | 主入口 |
| 保证金池列表的"登记"快捷操作（v1.7.99.341 建议）| `./margin-register.html?contractNo={合同编号}` | 累加登记场景 |

- **v1.7.99.341**：

## 2. 业务流程全景

```mermaid
flowchart TB
    A[合同签订 + 系统按敞口比例计算应付保证金] --> B[业务人员发起登记]
    B --> C{入口?}
    C -->|保证金池抽屉| D[点"登记保证金"]
    C -->|列表操作列| D
    D --> E[进入 margin-register.html?contractNo=...]
    E --> F[合同信息自动回显 12 字段]
    F --> G[登记信息 section:<br/>① 应付保证金<br/>② 已付保证金 = 历年累计<br/>③ 本次登记保证金金额<br/>④ 等比例冲抵货款配置（v1.7.99.342 徽标回显）]
    G --> H{校验}
    H -->|本次登记金额 > 0 且 为数字| I[顶部'剩余未付金额'实时更新]
    H -->|本次登记金额 ≤ 0 或非数字| X[禁用提交按钮 + 红字提示]
    I --> J[业务人员实际打款 线下完成]
    J --> K[上传凭证附件]
    K --> L[点击提交]
    L --> M[二次确认弹窗]
    M -->|确定| N[提交成功 toast + 跳保证金池]
    M -->|取消| O[保留页面数据]
```

**关键决策**：
- **线下打款 + 系统流程化登记**（来自 02.14 资金管理规范）：本页面不发起线上扣款，业务人员在线下完成银行转账后，回系统登记 + 上传凭证
- **登记页只读、等比例冲抵配置在保证金池页**：避免重复入口；登记时如果改了"等比例冲抵"会冲突，所以只能在保证金池调整

## 3. 字段规则

### 3.1 合同信息（12 字段，3 列 × 4 行，只读）

合同信息自动从 URL 参数 `contractNo` 回显，业务人员**不可修改**——校验合同归属。

| 字段 | 类型 | 必填 | 校验 |
|------|------|------|------|
| 销售订单/单批次合同编号 | input | - | 灰置，与合同池对应 |
| 合同编号（批次合同有 2 级时）| input | - | 灰置 |
| 买方企业 | input | - | 灰置 |
| 卖方企业 | input | - | 灰置 |
| 品名 | input | - | 灰置 |
| 业务类型 | select | - | 灰置（存货业务/预付业务/账期业务/购销业务）|
| 签订日期 | date | - | 灰置 |
| 合同数量（吨）| input | - | 灰置 |
| 当前保证金比例 | input | - | 灰置（来自保证金池）|
| 当前保证金金额（元）| input | - | 灰置（来自保证金池）|
| 付款总金额（元）| input | - | 灰置（来自保证金池）|
| 已回款总金额（元）| input | - | 灰置（来自保证金池）|

### 3.2 登记信息（v1.7.99.338 + 341 改版）

| 字段 | 类型 | 必填 | 默认值 | 校验 |
|------|------|------|--------|------|
| 应付保证金金额（元）| input | 是 | 系统带入应付额 = `敞口金额 × 应付比例%`（来自保证金池） | 灰置不可改；如需修改需回到保证金池调整"应付比例" |
| 已付保证金金额（元）| input | - | 系统带入历史缴存累计 | 灰置不可改 |
| **本次登记保证金金额（元）** | input | 是 | 0 | 必填，**正整数/正小数均可**；不能 ≤ 0；保留 2 位小数 |
| 等比例冲抵货款 | badge | - | 来自保证金池当前配置（v1.7.99.342 徽标回显） | 只读，不在登记页修改 |
| 已开启：冲抵比例 `X%` | - | - | - | 当保证金池状态=on |
| 未开启 | - | - | - | 当保证金池状态=off |

**v1.7.99.338 改动**：
- "应付"和"已付"**换行显示**（旧版一行 2 列）
- "本次登记保证金" 单独占整行，配灰色提示"线下打款 + 上传凭证后输入金额登记"

**v1.7.99.341 改动**：
- 顶部"剩余未付保证金金额 = 应付 - 已付 - 本次"实时计算条（v1.7.99.349 增加快捷按钮"补足剩余"/"本次付清"）

### 3.3 凭证附件

| 字段 | 类型 | 必填 | 校验 |
|------|------|------|------|
| 附件列表 | upload | **必填**（v1.7.99.341 强化）| 凭证图片 / PDF；至少 1 个；单文件 ≤ 10MB |
| 附件说明 | input | 否 | 选填，最多 100 字符 |

**v1.7.99.341 决策**：登记必须上传凭证——避免"口头登记无凭证"的合规漏洞。

### 3.4 等比例冲抵配置（v1.7.99.342 改版后只读）

**v1.7.99.342 关键改动**：

- ❌ 旧版：登记页提供 `switch`（开启/关闭）等比例冲抵 + 可填冲抵比例
- ✅ v1.7.99.342：登记页只回显保证金池的当前配置（徽标 + 比例值），不允许在此页面修改
- 改配置须回保证金池列表页调整（详见 `p-margin-pool.md` v1.7.99.346）

| 显示 | 含义 |
|------|------|
| `【已开启 冲抵比例 X%】` | 保证金池已开启等比例冲抵；本次登记完成后，未来付款按 X% 冲抵保证金 |
| `【未开启】` | 保证金池未开启；本次登记完成后，未来付款按正常流程付款 |

## 4. 按钮交互

### 4.1 主操作按钮

| 按钮 | 位置 | 行为 |
|------|------|------|
| **提交** | 底部固定 | 点击进行二次确认，确认后写入"保证金流水"（margin-record）+ 跳到保证金池 toast |
| **取消** | 底部固定 | 二次确认（"取消后已填写数据不会被保存"）|

### 4.2 快捷按钮（v1.7.99.349）

| 按钮 | 位置 | 行为 |
|------|------|------|
| 补足剩余 | 顶部"剩余未付金额"条右侧 | 自动填充"本次登记 = 应付 - 已付" |
| 本次付清（=补足剩余） | 同上 | 同上 |

### 4.3 辅助按钮

| 按钮 | 位置 | 行为 |
|------|------|------|
| + 上传 | 凭证区域 | 弹文件选择；支持图片/PDF；上传后列表显示文件名 + 大小 + 时间 + 删除按钮 |
| 删除附件 | 单附件右侧 | 二次确认后删除 |

### 4.4 二次确认弹窗

- **取消确认弹窗**：
  - 标题：取消确认
  - 内容：取消后，已填写的本次登记金额和凭证附件将不会被保存
  - 按钮：取消 / 确定

- **提交确认弹窗**：
  - 标题：提交确认
  - 内容：确认提交本次保证金登记？提交后系统将按本次登记金额更新保证金池"已付金额"
  - 按钮：取消 / 确定
  - 成功后 toast："保证金登记成功，已写入保证金流水"

## 5. 异常处理

| 场景 | 处理 |
|------|------|
| 本次登记金额 ≤ 0 或非数字 | 禁用提交按钮 + 红字提示"金额必须大于 0" |
| 未上传凭证附件 | 禁用提交按钮 + 红字提示"请上传本次打款凭证" |
| 合同信息缺失（合同不存在）| 顶部红色 bar 提示"该合同不存在或已作废" + 提供返回保证金池按钮 |
| 合同已作废 | 顶部红色 bar 提示"该合同已作废，无法登记保证金" |
| 合同已结清（已付 ≥ 应付）| 顶部橙色 bar 提示"该合同保证金已足额，登记会超额" + 提供"查看保证金池"链接 |
| 同一合同并发登记 | 提交时二次校验已付金额，如已被另一笔登记覆盖则提示"已被其他登记覆盖，请刷新后重试" |

## 6. 跨模块流转

### 6.1 与保证金池（margin-pool）联动

- 登记提交成功 → 保证金池该行"已付保证金金额" += 本次登记金额
- 保证金池的"敞口金额 / 应付保证金"不变（应付比例不变的前提下）

### 6.2 与保证金流水（margin-record，待补 PRD）

- 每次登记 → 生成 1 条 `type=登记` 的保证金流水
- 流水字段：登记时间、登记人、合同编号、本次登记金额、凭证附件、登记后保证金余额

### 6.3 与等比例冲抵配置（保证金池页）

- 登记时按当前保证金池的"等比例冲抵"状态写入流水备注
- 保证金池改状态不影响**已登记**的金额——只影响**未来付款**按新比例冲抵

### 6.4 与客户额度（02.02）

- 保证金池"已付金额"增加 → 系统不直接重算客户额度（**保证金不等同于回款**）
- 但敞口金额 = 付款总 - 回款总（不变），所以敞口比例会下降
