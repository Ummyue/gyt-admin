## 1. 业务定位

**v1.2.0 把编排页改成两步向导**，并把「属性编辑」从常驻侧栏改为右侧抽屉。

| v1.1.0 的问题 | v1.2.0 的处理 |
|---|---|
| 基础信息（名称/说明/状态）挤在画布上方，占掉首屏 | 独立为**步骤 1 基础信息**，画布独占整屏 |
| 应用模块在画布下方，需长距离滚动 | 移入**步骤 1** |
| 右侧常驻属性面板占 340px，画布被压窄 | 属性改为**点击节点弹出右侧抽屉**，画布满宽展开 |
| 顶部「+ 串行审批 / + 并行会签 / + 条件分支」按钮行 | 去掉；改为**点连接线上的 + 弹出选项卡片**，插入位置明确 |
| 流程图预览是画布下方一段横向节点条，弱 | 改为**弹窗 + 审批详情同款时间线**，可直接看到审批人和提醒 |

**入口**：`approval-flow-list.html` 的「编排」按钮 / 「新建流程」按钮
**URL 约定**：`approval-flow-editor.html?flowId={flowId}`，新建用 `?flowId=new`

> v1.2.0 起**新建与编辑共用同一套两步向导**（不再区分新建/编辑布局）。


## 3. 步骤条

| 元素 | 规则 |
|---|---|
| 步骤数 | **仅 2 步**：① 基础信息 ② 流程设计 |
| 当前步 | 蓝色实心圆 + 蓝色药丸底 |
| 已完成步 | 绿色圆 + `done` 类（回到步骤 1 时显示） |
| 点击 | 可直接切换；切到步骤 2 前跑一次基础信息校验，不通过则弹 Alert 并留在步骤 1 |
| 新建默认 | 停在步骤 1 |
| 编辑默认 | 停在步骤 1（与新建一致） |

**顶部常驻区**：返回 · 流程名称（超长省略）· 状态 tag · 未保存标记 ‖ 步骤条 ‖ 流程图预览 · 保存

## 4. 步骤 1：基础信息

| 字段 | 控件 | 必填 | 校验 |
|---|---|---|---|
| 流程名称 | input（40 字上限） | ✅ | 为空拦截进入步骤 2 与保存 |
| 流程说明 | textarea（2 行） | - | — |
| 流程状态 | 单选：草稿 / 启用 / 停用 | ✅ | 草稿仅自己可见 |
| 应用模块 | 多选（8 项 checkbox）+ 3 项带**子项复选下拉** | ✅ | 至少 1 个；带子项的至少 1 个子项 |

**保存行为**：顶部「保存」按钮在两步中都可用，随时可点；保存成功后回列表页并 toast。
步骤 1 底部另有「下一步：流程设计」，步骤 2 底部有「上一步：基础信息」。

**未保存标记**：任一字段改动后，顶部出现「● 有未保存的修改」；点「返回」时二次确认。

## 5. 步骤 2：流程设计（画布）

### 5.1 画布布局

- **满宽展开**：不再有右侧常驻属性面板，画布宽度 = 内容区全宽
- 节点卡片 200px 宽，横向排列，超出自动换行
- 连接线 `60px`，中间一个 `+` 圆形按钮

### 5.2 插入节点：选项卡片

点击连接线上的 `+`，在该连接线**正下方**弹出选项卡片（220px 宽，白底圆角阴影）：

| 顺序 | 选项 | 图标色 | 说明 |
|---|---|---|---|
| 1 | 串行审批 | 蓝 | 单人依次审批，逐级通过 |
| 2 | 并行会签 | 紫 | 多人同时收到，全部通过才算过 |
| 3 | 条件分支 | 橙 | 按字段阈值自动增减节点 |

- 同一时刻只展开一张卡片（点其他 `+` 会切换）
- 点击画布空白处收起
- 选中后**立即插入并打开该节点的属性抽屉**

### 5.3 节点卡片

| 区域 | 内容 |
|---|---|
| 序号圆点 | ①②③…，颜色 = 审批人所属部门色 |
| 节点名 | 超长省略，hover 显示全名 |
| 操作区 | `↑` 上移 / `↓` 下移 / `×` 删除（发起与归档禁用） |
| 类型标签 | 发起 / 串行审批 / 并行会签 / 条件分支 / 归档 |
| 人员行 | 👤 姓名 + 脱敏手机号（会签显示全部成员） |
| 提醒行 | ⏰ 未处理满 Nh 提醒（仅开启提醒的节点） |

**发起 / 归档节点**不显示人员行，分别显示「发起人提交，系统自动记录」「系统自动归档」。

### 5.4 节点属性 → 右侧抽屉

点击节点卡片打开**平台统一右侧抽屉**（`.ap-drawer`，与流程监控的「审批详情」同一套容器与视觉，宽度 520px）。

| 抽屉区域 | 内容 |
|---|---|
| 头部 | 标题「节点属性」+ 副标题「① · 业务审批 · 串行审批」+ 关闭 × |
| 主体 | 节点属性表单（见 §5） |
| 底部 | 关闭 · 完成 |

发起 / 归档节点打开抽屉时展示只读信息（节点类型 + 「系统节点，属性不可编辑」）。

## 6. 流程图预览（弹窗）

点击顶部「流程图预览」打开弹窗（720px 宽，居中，带遮罩），**不再是画布下方的一段文字条**：

| 区域 | 内容 |
|---|---|
| 头部 | 流程名称 + 副标题（应用模块 + 状态 tag）+ 关闭 × |
| 摘要区 | 流程名称 / 节点总数 / 模拟金额 / 分支结果 |
| **审批节点流转** | **引擎渲染的时间线**，与业务单据「审批详情」完全一致：节点序号圆点、状态 chip、审批人姓名 + 脱敏手机号 + 部门、提醒规则说明 |
| 条件分支求值明细 | 条件 / 操作符 / 阈值 / 实际值 / 结果 / 命中节点（6 列表格） |

| 模拟金额 | 时间线节点 |

| 3,000,000 | 提交申请 → 业务审批 → 风控财务会签 → **总经理审批（条件命中）** → 归档完成 |

## 7. 节点属性（字段清单）

| 节点类型 | 抽屉内属性项 | 说明 |
|---|---|---|
| 发起 / 归档 | 只读信息卡 | 系统节点，不可编辑 |
| 串行审批 | 节点名称、**审批人员**、**提醒规则**、节点说明 | — |
| 并行会签 | 节点名称、**会签人员**、**提醒规则**、节点说明 | 会签成员选人 |
| 条件分支 | 节点名称、**条件规则**、节点说明 | 无提醒规则 |

### 7.1 审批人员

- **来源**：`ApprovalEngine.PEOPLE` 平台人员目录（原型 Mock，接真实组织架构后只换数据源）
- **展示格式**：`完整姓名  脱敏手机号`（如 `张磊  138 0000 XXXX`）
- **存储**：节点上的 `approver: 'u_biz_01'`（人员 id）
- **节点配色**：按人员所属部门取色

### 7.2 提醒规则

```js
remind: { enabled: true, afterHours: 24 }
```

| 控件 | 说明 |
|---|---|
| 开启审批提醒（复选） | 关闭后小时数禁用，卡片与预览中的提醒行消失 |
| N 小时（1~720） | 未处理满 N 小时后推送站内消息 + 短信 |

### 7.3 会签人员

- 每人一个下拉 + 删除按钮；同一人不能重复；至少 1 人
- 新增时自动选一个尚未加入的人员

### 7.4 条件规则

| 控件 | 选项 |
|---|---|
| 字段 | 单据金额 / 业务类型 / 合同类型 / 客户等级 / 风险等级 |
| 操作符 | > ≥ < ≤ = ≠ |
| 阈值 | 数字输入 |
| 命中时追加节点 | 审批环节下拉 |

命中后自动带出该环节的**默认审批人**（`ROLES[key].defaultPerson`）。

## 8. 应用模块级联规则（v1.4.0：子项改复选下拉）

### 8.1 界面形态

应用模块仍是 8 个 checkbox 的两列网格。**合同管理 / 货转管理 / 结算单管理** 三个带子项的模块，
在 checkbox 右侧带一个**子项复选下拉**；子项不再向下平铺展开，默认隐藏。

```
☐ 项目准入                          ☐ 合同管理  [ 全部（2）              ▾ ]
☐ 货转管理  [ 请选择子项  ▾（禁用）]  ☐ 付款管理
☐ 退款管理                          ☐ 结算单管理[ 全部（2）              ▾ ]
☐ 追保函管理                        ☐ 放货管理
```

| 状态 | 触发器文案 | 说明 |
|---|---|---|
| 父模块未勾选 | `请选择子项` | 触发器置灰 `is-disabled`，不可点开 |
| 子项全选 | `全部（2）` | 勾父级时的默认态 |
| 仅选 1 个 | `销售合同` | 直接显示子项名 |
| 选了多个但不满 | `采购合同 等 2 项` | 首项 + 计数 |

**下拉面板**：顶部「全选 / 清空」快捷链接 + 子项 checkbox 列表（当前每模块 2 项）。
点面板外空白收起；点子项后**面板保持展开**（重渲染时按 `openDD` 恢复展开态）。

### 8.2 级联规则

| 操作 | 行为 |
|---|---|
| 勾选**无子项**模块 | 直接生效，不显示下拉 |
| 勾选**带子项**模块（合同/货转/结算单） | 自动**全选**其子项，下拉显示「全部（2）」 |
| 下拉内单独取消某个子项 | 仅该子项退出，父级保持选中；文案变「销售合同」等 |
| 下拉「清空」 | 子项全清 → **父级自动取消勾选**，触发器回到禁用态 |
| 下拉「全选」 | 子项全选，父级保持选中 |
| 进入步骤 2 / 保存时父级选中但无子项 | Alert「『xxx』已勾选，请至少选择一个应用子项」并留在步骤 1 |

**存储结构**（v1.1.0 起未变，v1.4.0 仅改交互形态）：

```js
applyModules: [
  { key: 'contract',       children: ['contract_purchase', 'contract_sales'] },
  { key: 'goods_transfer', children: ['transfer_up'] },
  { key: 'payment',        children: [] }
]
```

## 9. 保存校验

| 校验 | 提示 | 落点 |
|---|---|---|
| 流程名称为空 | 请填写流程名称 | 步骤 1 |

## 12. 字段规则

### 12.1 流程模板

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 内置 `standard`/`simple`/`highRisk`；新建 `flow_{时间戳}` |
| `name` | text | 流程名称 |
| `desc` | text | 流程说明 |
| `status` | enum | `draft` / `enabled` / `disabled` |
| `applyModules` | array | 应用模块，结构见 §8 |

### 12.2 节点

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 节点唯一标识 |
| `type` | enum | `start` / `serial` / `parallel_all` / `branch` |
| `name` | text | 节点显示名 |
| `roleKey` | enum | 审批环节 key（分支指向 + 默认配色用） |
