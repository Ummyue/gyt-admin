# 02.18 审批管理 · 通用审批流程监控

> **页面**：`approval-monitor.html`
> **版本**：v1.1.0（2026-10-15）
> **模块归属**：数字供应链 → 审批管理 → 审批流程监控
> **引擎**：`shared/js/approval-engine.js` v1.1.0（与编排画布共用同一份配置）

---

## 1. 业务定位

**审批流程监控**是审批链路的运行态视图，回答管理员三个问题：

| 问题 | 本模块怎么回答 |
|---|---|
| 现在有多少单子卡在审批里？ | 顶部 4 个 KPI：实例总数 / 审批中 / 已通过 / 已触发提醒 |
| 卡在哪一步、谁在审？ | 列表「当前节点」+「当前审批人」两列 + 详情抽屉完整时间线 |
| 金额条件分支把流程改成什么样了？ | 详情抽屉内展示**逐条规则求值明细**（命中/未命中、各自阈值） |

**与配置页的关系**：配置页管「流程应该怎么走」（设计态），监控页管「实际走到哪儿了」（运行态）。两者读同一份 `localStorage['ygt_approval_flow_templates_v1']`，配置一改，监控页下次打开即按新流程展开节点。

四张卡片随下方筛选条件**联动重算**。

### 3.3 筛选区（2 个实时筛选器）

### 3.4.1 审批提醒记录（v1.1.0 新增）

独立区块，展示编排画布配置的提醒规则触发后的推送记录（8 列）：

| 列 | 内容 |
|---|---|
| 单据编号 | 关联的审批实例 |
| 应用模块 | 该实例所属模块 |
| 卡在节点 | 触发提醒的节点名 |
| 提醒对象 | 审批人姓名 + 脱敏手机号 |
| 提醒阈值 | 「未处理满 Nh」 |
| 推送渠道 | 站内消息 + 短信 |
| 触发时间 | 提醒发送时间 |
| 状态 | 已送达 / 待送达 |

### 3.5 详情抽屉

打开后展示三块内容：

1. **单据摘要**（12 项）—— 应用模块、单据金额、引用流程、发起人、提交时间、当前节点、**当前审批人**、已耗时、**提醒规则说明**
2. **审批时间线** —— 用 `ApprovalEngine.renderTimeline()` 按该实例引用的流程渲染。串行节点会显示审批人姓名 + 脱敏手机号，会签节点逐人列出
3. **条件分支求值明细** —— 逐条列出条件 / 操作符 / 阈值 / 实际值 / 结果 / 命中节点

> 无分支的流程（`simple` / `highRisk`）不显示第 3 块。

### 4.2 Mock 数据说明

原型阶段为前端 Mock，固定 10 条实例，覆盖：

- 3 种流程模板（`standard` / `simple` / `highRisk`）
- 4 种状态（审批中 / 已通过 / 已驳回 / 已撤回）
- 金额跨 100 万阈值（18 万 / 32 万 / 68 万 / 95 万 / 150 万 / 220 万 / 320 万 / 500 万），确保条件分支命中与未命中都有样本

> 所有姓名、企业、金额均为**脱敏 Mock 数据**，不含真实客户信息。

## 5. 按钮交互

| 按钮 | 位置 | 行为 |
|---|---|---|
| 详情 | 列表行 | 打开右侧抽屉，展示时间线 + 分支求值明细 |

> **催办/撤回为原型演示交互**，不改变实例状态，也不写回任何后端。真实版本需接消息网关 + 撤回权限校验。

## 6. 异常处理

| 异常 | 表现 | 处理 |
|---|---|---|
| 引用的流程模板已被删除 | 打开详情 | `getFlow()` 返回 null → 回退 `standard`，时间线仍可渲染 |
| 流程配置在本会话被改动 | 打开列表 | 下次进入抽屉按最新配置展开，时间线节点数可能变化 |
| 单据无金额 | 条件分支求值 | 条件判定 false → 分支节点标记「已跳过」，明细行显示「—」 |
| 筛选后无匹配实例 | 列表 | 显示空状态提示，可点 Tab 切回「全部」 |
| localStorage 不可用 | 隐私模式 | `console.warn` 降级，使用内置默认流程配置 |

## 7. 跨模块流转

```
approval-flow-list.html（改流程配置）
      │  同一 localStorage key
      ▼
ygt_approval_flow_templates_v1
      │
      ▼
ApprovalEngine.getFlow(instance.flowId)
      │
      └─→ approval-monitor.html（详情抽屉按新配置渲染时间线）
      └─→ 14 个业务页面（读 APPROVAL_CONFIG_BY_PAGE 找到 flowId → 渲染时间线）
```

**关键约束**：配置存 `localStorage`，**同一浏览器**内配置页改动会实时影响监控页与业务页面；跨浏览器不同步（原型阶段限制）。

## 8. 技术实现要点

### 8.1 时间线复用

监控页**不另写一套时间线渲染**，直接调用引擎。v1.1.0 起，串行节点也会
渲染审批人员行（姓名 + 脱敏手机号），与业务页面完全一致：

```js
ApprovalEngine.renderTimeline({
  flow:   ApprovalEngine.getFlow(instance.flowId),
  formData: { amount: instance.amount },   // 供条件分支求值
  currentIdx: instance.currentNodeIdx
});
```

好处：配置页新增节点，监控页自动跟着变，不存在两套 UI 逻辑漂移。

### 8.2 分支求值明细

明细不自己算，直接复用引擎的 `evalBranch()` 返回值（**已求值**的 `res.rules`）：

```js
const node = flow.nodes.find(n => n.type === 'branch');
const res  = ApprovalEngine.evalBranch(node, { amount: instance.amount });
res.rules.forEach(r => r.matched ? 命中 : 未命中);
```

> ⚠️ 必须读 `res.rules`（已求值，含 `matched`），不能读 `node.condition`（原始配置，无 `matched` 字段）。详见 `p-approval-flow-list.md` §11.1。
