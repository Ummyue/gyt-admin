## 2. 业务规则（v1.7.99.206 新增——按图1 重写）

### 2.1 合规验证报告生成规则

**生成方式**：系统启动**定时任务**，每个 1 小时按如下条件检查一次：

- 当监测到业务线上关联有**状态为【已付款】的付款记录**时，生成业务线合规报告

**业务定位**：
- 合规验证报告以"业务线"为单位生成（不是合同、不是项目、不是订单）
- 每条业务线对应一份合规验证报告
- 业务线状态变化（新增/付款/完结）触发报告重新生成

### 2.2 搜索条件

**搜索条件同【数字供应链】-【业务线管理】搜索条件**（v1.7.99.206 锁定——10 字段）：

| # | 搜索字段 | 类型 | 搜索规则 / 提示语 |
|---|---------|------|------------------|
| 1 | 编号 | text | 订单、合同、业务线号，**精确搜索**，提示语："请输入订单、合同、业务线号"，**长度 100 以内** |
| 2 | 企业名称 | text | 支持按**业务线上的上游企业-业务主体-下游企业三方企业名称**以及**业务线名称**进行搜索，**模糊搜索**，提示语："请输入企业名称、业务线名称" |
| 3 | 运输方式 | select | 下拉枚举：火运 / 汽运 / 船运 / 汽运和火运 / 不涉及运输 |
| 4 | 签订日期 | date-range | 根据业务线上**采购订单/合同的签订日期**进行搜索，**日期范围控件** |
| 5 | 交货起始日 | date-range | 根据业务线上**采购订单/钢订单/合同的签订日期**进行搜索，**日期范围控件** |
| 6 | 业务类型 | select | 选填，下拉枚举：全部 / 存货类 / 预付类 / 账期类 / 购销类 |
| 7 | 业务线回款 | radio | 单选，下拉列表：选填值为已回款 / 未回款 |
| 8 | 已回款 | condition | **业务线上关联有认领类型为"货款"的回款认领记录**（隐含条件，自动应用）|
| 9 | 未回款 | condition | **业务线上未关联有认领类型为"货款"的回款认领记录**（隐含条件，自动应用）|

**v1.7.99.206 决策**：
- "已回款 / 未回款"是**互斥的 radio 单选项**（v1.7.99.206 锁定）—— 选了"已回款"就只显示已回款的业务线，选"未回款"只显示未回款的
- "业务线回款"是 radio 的视觉占位（label 名），实际值是"已回款 / 未回款"
- 三个搜索字段（业务线回款/已回款/未回款）在 v1.7.99.206 改写中合并为 1 个 radio（业务线回款单选：已回款/未回款）

### 2.3 列表说明

**取值条件**：当前登录账号**所属企业**下的所有业务线数据。

**v1.7.99.206 决策**：
- 不是"系统所有业务线"，是**当前登录账号所属企业**的业务线（数据权限隔离）
- 不同账号看到不同业务线集合（按企业隔离）

## 6. 数据规则（v1.7.99.206 新增——按图1 字段表"备注"列）

### 6.1 业务线取值规则

直接取业务线主表"业务线名称"字段。

### 6.2 数据完善状态取值规则

**取上下游数据的状态合开展示**（合并上游/下游状态为一行文字）。

### 6.3 资金来源取值规则

取该业务线中**所有的付款记录的资金类型值**，以逗号隔开，**与业务动态监控列表中保持一致**。

### 6.4 合同状态取值规则

取上下游的合同状态，**单签状态时为红字显示**。

### 6.5 预警数取值规则

取业务线上下游的**待处理及流程中的预警总数**，其中**删除"已处理"、"已处理（人工）"状态的预警**，当预警数 ≥ 1 时为**红字显示**。

### 6.6 材料完善度取值规则（v1.7.99.206 关键——按图1 详细规则）

**上下游分开计算材料完善度**，计算规则：

**全部申报类型**（v1.7.99.206 锁定——9 类）：
- 上游双签合同
- 中游双签合同
- 下游双签合同
- 上游发票（状态正常）
- 下游发票（状态正常）
- 上游货转（已盖章）
- 下游货转（已盖章）
- 上游结算单（已盖章）
- 下游结算单（已盖章）

**计算公式**：
- 上游材料完善度 = 符合上游条件约束的材料个数 / 5 × 100%
- 下游材料完善度 = 符合下游条件约束的材料个数 / 5 × 100%

**v1.7.99.206 决策**：
- 上游/下游**各计算 5 个材料类型**（不是 9 个）—— 上游对应 5 类：双签合同/发票/货转/结算单/付款单（"中游双签合同"不属于上游专属）
- 实际申报材料**按上下游业务线**区分（上游业务线用上游材料 / 下游业务线用下游材料）
- 材料完善度展示为"上游 X% / 下游 Y%"两段式（v1.7.99.200 原型已实现）

### 6.7 业务线号取值规则

直接取业务线主表"业务线号"字段。

### 6.8 业务状态取值规则

取当前业务线的状态（业务线主表"状态"字段）。

## 7. 异常处理（v1.7.99.206 新增）

### 7.1 业务线删除后报告处理

- 业务线被解除（v1.7.99.202 操作下拉）→ 对应合规验证报告**保留但不更新**（历史快照）
- 列表中已解除业务线的报告仍可见，但点击"查看报告"打开后提示"该业务线已解除，报告为历史快照"

### 7.2 付款记录回滚处理

- 当触发报告生成的"已付款"记录被回滚（v1.7.99.199 状态机调整）→ 已生成的报告**不删除**，但下次定时任务会重新检查并按当前状态重新生成

### 7.3 业务线跨企业查询

- 当前账号所属企业 A，尝试查询企业 B 的业务线 → 列表**不展示**企业 B 的业务线（数据权限隔离）
- 搜索框输入企业 B 的业务线号 → 提示"无权限查看"（按 § 2.3 取值条件）

## 8. 跨模块流转

### 8.1 报告生成触发链

```
定时任务（每 1 小时）
  ↓
检查业务线付款记录
  ↓
监测到业务线上关联有【已付款】的付款记录
  ↓
生成业务线合规报告（report-compliance-detail.html 数据初始化）
  ↓
列表页 report-compliance.html 显示该业务线报告
```

### 8.2 与业务线详情页联动

- 列表"业务线"列 / "业务线号"列 link → 跳业务线详情页 `business-line-detail.html`
- 业务线详情页 v1.7.99.202 "操作"下拉 → "查看合规验证报告"（v1.7.99.203）→ 跳到本详情页

### 8.3 与数字供应链业务线管理联动

- 搜索条件**完全沿用**【数字供应链】-【业务线管理】的搜索条件（编号/企业名称/运输方式/签订日期/交货起始日/业务类型/业务线回款/已回款/未回款）
- 搜索逻辑保持一致

### 8.4 与预警中心联动

- 列表"预警数"列 link → 跳预警列表 `warning-list.html?bizline=xxx`
- 详情页"合作期间主体风险监控情况"表数据 → 来自预警表的分类统计

### 8.5 与付款管理联动

- 报告生成触发条件 = 付款记录的"已付款"状态
- 详情页"上下游付款"区块数据 → 来自付款管理表
