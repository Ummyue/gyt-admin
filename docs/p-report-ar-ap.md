## 1. 业务定位

**应收应付明细表（按业务线汇总）**是数据中心的 6 张业务报表之一——按"业务线"维度汇总应收、应付、资金占压数据（业务线号 / 采购合同编号 / 上下游客户 / 上游应付-已付-未付-进项发票 / 下游应收-已收-未收-销项发票 / 库存资金占压-净占压金额），是业务线维度资金占压全链路数据查询入口。

> **v1.7.99.220 重写背景**：v1.7.99.200 旧版"应收应付表"是按"单据"维度（每行 = 1 张 AR 单 / AP 单），存在 3 个问题：① 维度太细，业务线维度的资金占压需要手动累加；② 字段缺失（没有资金占压、净占压、上下游客户关联）；③ 顶部 4 KPI（应收总额/已收/未收/应付总额）只覆盖金额，没有库存资金占压和净占压。新版改为"业务线"维度（每行 = 1 条业务线），**所有金额/发票状态/资金占压都按业务线汇总**，让业务线维度的资金占压一目了然。

| 字段 | 数据来源 | 公式 |

| 字段 | 数据来源 | 规则 |

| 字段 | 数据来源 | 规则 |
|------|----------|------|
| 上游应付（元） | t_settlement_upstream 结算单 | 公式 1：SUM(含税结算金额) |
| 上游已付（元） | t_payment_record 付款记录 | 公式 2：SUM(金额 WHERE 状态='已付款') |
| 上游未付（元） | 计算 | 公式 3：上游应付 - 上游已付 |
| 进项发票 | t_invoice_in 入库发票 | 公式 4：4 状态聚合（已开/部分/未开/待开） |

### 3.4 下游（销售/应收）字段

| 字段 | 数据来源 | 规则 |
|------|----------|------|
| 下游应收（元） | t_settlement_downstream 结算单 | 公式 5：SUM(含税结算金额) |
| 下游已收（元） | t_receipt_flow 回款流水 + t_refund 退款 | 公式 6：SUM(回款 WHERE 认领类型='货款' AND 状态='已认领') - SUM(退款 WHERE 状态='已退款') |
| 下游未收（元） | 计算 | 公式 7：下游应收 - 下游已收 |
| 销项发票 | t_invoice_out 出库发票 | 公式 8：4 状态聚合（已开/部分/未开/待开） |

### 3.5 资金占压字段

| 字段 | 数据来源 | 规则 |
|------|----------|------|
| 库存资金占压 | t_inbound + t_outbound | 公式 9：SUM(入库金额×入库单价) - SUM(出库金额×出库单价) |
| 净占压金额 | 计算 | 公式 10：下游未收 + 库存资金占压 - 上游未付 |

## 5. 数据取值逻辑公式（**核心 10 条**）

### 公式 1：上游应付（元）

> 该业务线下**所有上游结算单的含税结算金额**合计。

```sql
SELECT SUM(t_settlement_upstream.tax_included_amount)
FROM t_settlement_upstream
WHERE t_settlement_upstream.bizline_id = #{bizlineId}
  AND t_settlement_upstream.status = 'effective'
```

### 公式 2：上游已付（元）

> 该业务线下**所有状态为"已付款"的付款记录**金额之和。

```sql
SELECT SUM(t_payment_record.amount)
FROM t_payment_record
WHERE t_payment_record.bizline_id = #{bizlineId}
  AND t_payment_record.status = '已付款'
```

### 公式 3：上游未付（元）

> 上游应付 - 上游已付。

```sql
上游未付 = 上游应付 - 上游已付  -- 见公式 1 + 公式 2
```

### 公式 4：进项发票

> **入库发票状态聚合**——按业务线下所有入库发票的开票状态聚合为 4 种 tag：
> - **已开**（绿色 tag）—— 入库发票全部开票完成
> - **部分**（橙色 tag）—— 入库发票部分开票
> - **未开**（红色 tag）—— 入库发票未开票
> - **待开**（灰色 tag）—— 入库发票待开票（暂未触发开票）

```sql
SELECT
  CASE
    WHEN COUNT(DISTINCT t_invoice_in.invoice_id) = SUM(t_invoice_in.status = '已开') THEN '已开'
    WHEN SUM(t_invoice_in.status = '已开') > 0 THEN '部分'
    WHEN SUM(t_invoice_in.status = '未开') = COUNT(*) THEN '未开'
    ELSE '待开'
  END AS invoice_status
FROM t_invoice_in
WHERE t_invoice_in.bizline_id = #{bizlineId}
```

### 公式 5：下游应收（元）

> 该业务线下**所有下游结算单的含税结算金额**合计。

```sql
SELECT SUM(t_settlement_downstream.tax_included_amount)
FROM t_settlement_downstream
WHERE t_settlement_downstream.bizline_id = #{bizlineId}
  AND t_settlement_downstream.status = 'effective'
```

### 公式 6：下游已收（元）

> 该业务线下**所有已认领的回款流水**金额合计（认领类型为"货款"）- 所有状态为"已退款"的**退款金额**之和（注意退款是对下游客户的货款退款）。

```sql
SELECT
  (SELECT SUM(t_receipt_flow.amount)
   FROM t_receipt_flow
   WHERE t_receipt_flow.bizline_id = #{bizlineId}
     AND t_receipt_flow.claim_type = '货款'
     AND t_receipt_flow.status = '已认领')
  -
  (SELECT SUM(t_refund.amount)
   FROM t_refund
   WHERE t_refund.bizline_id = #{bizlineId}
     AND t_refund.status = '已退款')
AS 下游已收
```

### 公式 7：下游未收（元）

> 下游应收 - 下游已收。

```sql
下游未收 = 下游应收 - 下游已收  -- 见公式 5 + 公式 6
```

### 公式 8：销项发票

> **出库发票状态聚合**——按业务线下所有出库发票的开票状态聚合为 4 种 tag：
> - **已开**（绿色 tag）—— 出库发票全部开票完成
> - **部分**（橙色 tag）—— 出库发票部分开票
> - **未开**（红色 tag）—— 出库发票未开票
> - **待开**（灰色 tag）—— 出库发票待开票（暂未触发开票）

```sql
SELECT
  CASE
    WHEN COUNT(DISTINCT t_invoice_out.invoice_id) = SUM(t_invoice_out.status = '已开') THEN '已开'
    WHEN SUM(t_invoice_out.status = '已开') > 0 THEN '部分'
    WHEN SUM(t_invoice_out.status = '未开') = COUNT(*) THEN '未开'
    ELSE '待开'
  END AS invoice_status
FROM t_invoice_out
WHERE t_invoice_out.bizline_id = #{bizlineId}
```

### 公式 9：库存资金占压

> **业务线累计入库金额 - 累计出库金额**。
>
> - 累计入库金额 = SUM(入库金额 × 入库单价)
> - 累计出库金额 = SUM(出库金额 × 出库单价)

```sql
SELECT
  (SELECT SUM(t_inbound.amount * t_inbound.unit_price)
   FROM t_inbound
   WHERE t_inbound.bizline_id = #{bizlineId})
  -
  (SELECT SUM(t_outbound.amount * t_outbound.unit_price)
   FROM t_outbound
   WHERE t_outbound.bizline_id = #{bizlineId})
AS 库存资金占压
```

### 公式 10：净资金占压

> **下游未收 + 库存资金占压 - 上游未付**。

```sql
净资金占压 = 下游未收 + 库存资金占压 - 上游未付
           -- = 公式 7  +  公式 9  - 公式 3
```

> **v1.7.99.220 公式设计意图**：净占压金额反映"业务线维度的真实资金占压"——下游未收（应收但未到账）+ 库存占压（货在仓库没出）- 上游未付（应付但还没付出）= 平台真实占压的资金量。这是资金管理的核心 KPI。

## 6. 异常处理

| 场景 | 提示 | 公式影响 |
|------|------|----------|
| 业务线无上游结算单 | 上游应付/已付/未付/进项发票 全为 0 / "—" | 公式 1-4 返回 0/empty |
| 业务线无下游结算单 | 下游应收/已收/未收/销项发票 全为 0 / "—" | 公式 5-8 返回 0/empty |
| 业务线无入库/出库单 | 库存资金占压 = 0 | 公式 9 返回 0 |
| 上下游客户为空 | "（无下游客户）" 灰色文字 | 公式 5-8 全为 0 |
| 净占压金额为负数 | 红色字（负数用括号） | 公式 10 计算结果 |
