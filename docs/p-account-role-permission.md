## 1. 业务定位

**角色权限管理**是港通供应链的**RBAC 配置页**——企业管理员为角色勾选

- **可访问的菜单**（一级 / 二级 / 三级，共 7 + 67 个节点）
- **菜单内可执行的操作按钮**（199 个权限项，覆盖全部业务页面）
- **数据隔离范围**（全部数据 / 仅本人创建的数据）

角色是**权限的载体**：一个角色 = 一组菜单权限 + 一组操作权限 + 一个数据隔离范围。
员工绑定角色后，实际可见范围 = 角色权限 ∩ 数据隔离范围。

**页面入口**：账户中心 → 企业管理 → 角色权限管理（左侧 sidemenu 三级菜单）。

## 2. 核心实体

| 实体 | 说明 |
|------|------|
| 角色 Role | 名称、编码、描述、状态、关联用户数 |
| 菜单权限 Menu Permission | 一/二/三级菜单节点，每个节点一个权限码 |
| 操作权限 Operation Permission | 页面内每个操作按钮一个权限码 |
| 数据隔离范围 Data Scope | `all`（全部数据）/ `own`（仅本人创建的数据） |

### 2.1 权限项收敛口径（人工审核）

自动抽取会把页面上的**所有**按钮都收进来，其中混着弹窗确认键、面板工具条、文件操作等**噪音**，
需要人工逐项审核。审核结论写在 `scripts/extract_permissions.py` 的 `EXCLUDE_OPS` 剔除清单里：

```python
EXCLUDE_OPS = {
    "准入管理/项目准入":     {"确认上传", "全部标记已读", "查看", "替换", "删除"},
    "准入管理/客户准入":     {"查看状态机说明", "查看额度", "发起完结"},
    "准入管理/黑名单管理":   {"批量删除", "下载模板", "开始导入"},
    "账户中心/企业管理/角色权限管理": {"全选", "清空"},
}
```

- key = 菜单路径（与权限码路径一致），value = **要剔除的按钮名**
- 剔除项**不再出现在权限配置项里**，也就无法被分配给任何角色
- ⚠️ 被剔除的按钮**仍占用 scope 编号**，其余按钮的权限码与剔除前完全一致
  → 已保存角色的权限不会因为收敛而失效
- 其他模块后续同样审核时，往这个表里加即可，不用改逻辑

**准入管理模块审核结论（2026-11-09 user 逐项确认）**

| 菜单 | 原操作项 | 保留 | 剔除 |
|---|---|---|---|
| 项目准入 | 15 | 10：新增立项申请 / 数据导出 / 编辑 / 提交 / 作废 / 撤回 / 重新提交 / 上传客户准入报告 / 上传决议文件 / 发起完结 | 确认上传 / 全部标记已读 / 查看 / 替换 / 删除 |
| 客户准入 | 9 | 6：新增客户 / 数据导出 / 编辑 / 查看 / 撤回 / 作废 | 查看状态机说明 / 查看额度 / 发起完结 |
| 黑名单管理 | 7 | 4：新增黑名单企业 / 批量导入 / 数据导出 / 详情 | 批量删除 / 下载模板 / 开始导入 |

### 2.2 子节点并入（新增/编辑页不单列菜单）

「新增XXX」「编辑XXX」这类页面**不是独立菜单**，而是所属业务列表页下的操作入口，
不该各占一个可勾选的菜单节点。它们的可访问性由**右侧的操作权限项**控制。

实现：`scripts/extract_permissions.py` 的 `MERGE_CHILDREN` 表

```python
MERGE_CHILDREN = {
    "数字供应链/合同管理": {
        "采购合同": ["新增采购框架合同", "新增采购订单/单批次合同"],
        "销售合同": ["新增销售框架合同", "新增销售订单/单批次合同"],
        "补充协议": ["新增补协-框架合同", "新增补协-订单/单批次合同"],
    },
    "数字供应链/资金管理/回款管理": {
        "回款列表": ["回款详情", "回款审批详情", "编辑回款"],
    },
    "数字供应链/资金管理/保证金管理": {
        "保证金明细": ["保证金调整", "保证金调整记录"],
    },
    "数字供应链/审批管理": {
        "审批流程配置": ["流程编排画布"],
    },
}
```

效果：

| 菜单 | 树里的子节点 | 该节点的操作权限项 |
|---|---|---|
| 合同管理 | **采购合同 / 销售合同 / 补充协议**（3 个） | 采购合同 9 项（列表页 4 + 新增页 5）、销售合同 9 项、补充协议 9 项 |
| 回款管理 | **回款列表**（1 个） | 回款列表 13 项（列表页 5 + 审批详情 3 + 编辑回款 5） |
| 保证金管理 | **保证金明细**（1 个） | 保证金明细 10 项（明细页 3 + 调整 3 + 调整记录 4） |
| 审批管理 | **审批流程配置 / 审批流程监控**（2 个） | 审批流程配置 7 项（配置页 2 + 编排画布 5）、审批流程监控 3 项 |

- 被并入的菜单**不再出现在左树**，其操作权限项挂在宿主菜单下，每项带「来自 XXX」来源标签
- 被并入菜单的**菜单码记在宿主的 `mergedMenus`** 里 → 勾选宿主即隐含这些页面的访问权
- 被并入页面的**操作权限码保留原路径**（如 `数字供应链/合同管理/新增采购框架合同#upload`）
  → 已保存角色的权限不会因合并而失效
- 操作权限项总数不变，菜单节点随真实系统结构调整

### 2.4 权限项调整机制（v1.32.0）

权限项有**四种**来源，在 `scripts/extract_permissions.py` 里分表配置：

| 表 | 作用 |
|---|---|
| `EXCLUDE_OPS` | 从页面自动抽取的结果里**剔除**指定按钮（7 个菜单） |
| `EXPLICIT_OPS` | **全量替换**页面自动抽取结果，按人工清单定义（3 个菜单） |
| `ADD_OPS` | 保留原有项，**追加**新项（5 个菜单） |
| `MERGE_CHILDREN` | 把新增/编辑/详情页**并入**宿主菜单（4 处） |

### 2.5 权限码规则

| 类型 | 格式 | 示例 |
|------|------|------|
| 菜单权限 | `menu:<一级>/<二级>/<三级>` | `menu:数字供应链/合同管理/采购合同` |
| 操作权限 | `<菜单路径>#<scope>` | `数字供应链/合同管理/采购合同#export` |

- 菜单路径取自 `window.TOPNAV_MENU`，与真实导航一致
- `scope` 由按钮语义归一：`create / edit / delete / void / withdraw / submit / save / export / approve / reject / urge / upload / import / copy / print / view …`
- 一级模块的权限码为 `menu:<一级菜单名>`（如 `menu:数字供应链`）

## 3. 字段规则

### 3.1 角色列表

| 字段 | 类型 | 说明 |
|------|------|------|
| 角色名称 | 字符串 | 必填，≤ 20 字，同企业内不重复 |
| 角色编码 | 字符串 | 必填，`^[A-Za-z][A-Za-z0-9_]{1,31}$`，全企业唯一；新增时按名称自动生成 |
| 角色描述 | 文本 | ≤ 100 字 |
| 状态 | 枚举 | 启用 / 停用（停用后该角色成员无法登录） |
| 数据权限 | 枚举 | 全部数据（全局）/ 仅本人创建的数据 |
| 权限项 | 数字 | 已勾选的菜单 + 操作按钮总数 |
| 关联用户 | 数字 | 绑定该角色的成员数 |
| 更新时间 | 日期时间 | `yyyy-MM-dd HH:mm` |

### 3.2 数据隔离权限（角色级）

| 选项 | 含义 | 适用岗位 |
|------|------|----------|
| 全部数据（全局） `all` | 可查看并操作本企业全部业务数据，含他人创建的单据 | 管理员、主管、财务 |
| 仅本人创建的数据 `own` | 仅可查看并操作自己创建的单据，他人单据在列表中不可见 | 业务经办人、仓库操作员 |

> 口径：**角色级统一**，不区分模块。一个角色下所有成员共享同一数据范围。

## 4. 按钮交互

### 4.1 列表页（`account-role-permission.html`）

| 区域 | 元素 | 行为 |
|------|------|------|
| 标题区 | 新增角色 | 打开**居中弹窗**（1180px），空白表单 |
| 统计卡 | 角色总数 / 启用中 / 已关联用户 / 仅本人数据角色 | 随角色数据实时刷新 |
| 筛选区 | 角色名称或编码、数据权限、状态 | 关键字实时过滤；生成筛选 chip；「清除全部」一键重置 |
| 表格 | 角色名称（含图标 + 描述）、角色编码、数据权限徽标、权限项、关联用户、状态、更新时间、操作 | 列表默认 10 条/页，可切 20/50 |
| 操作列 | 查看权限 | 打开**右侧抽屉**（760px），只读展示该角色已授权的权限树 + 已授权操作按钮清单 |
| 操作列 | 编辑 | 打开**居中弹窗**，回显全部配置 |
| 操作列 | 删除 | 二次确认弹窗，说明影响范围，删除不可撤销 |

### 4.2 新增 / 编辑角色弹窗

**区块一 · 基本信息**
- 角色名称必填；角色编码按名称自动生成（中文名走语义词典，如「业务操作员」→ `ROLE_OPERATOR`；
  无法归一时取名称中的 ASCII 片段），用户手动改过后不再自动覆盖
- 编码重复校验：与已有角色重名时在字段下方红字提示「角色编码已存在：{角色名}」
- 状态：启用 / 停用

**区块二 · 数据隔离权限**
- 两个单选卡片（不是普通 radio input，是整卡可点）
- 切换后下方蓝色提示条文案同步变化，明确"能看到什么数据"
- 该设置对**整个角色**生效

**区块三 · 权限配置（左树 + 右按钮）**

| 元素 | 行为 |
|------|------|
| 左：菜单树 | 7 个一级模块 + 72 个二/三级菜单；四级缩进；每行显示该节点下的权限项数量 |
| 左：菜单搜索 | 按菜单名 / 权限码过滤，命中项的祖先一并保留 |
| 左：三角箭头 | 展开 / 收起子级 |
| 左：复选框 | **父子联动**：勾父即勾全部子孙菜单 + 全部操作按钮；勾子到不齐时父显示**半选态** |
| 左：点击菜单名 | 选中该节点，右侧切换到该菜单的操作权限 |
| 右：操作按钮区 | 网格展示该页面全部操作按钮，每项带权限码；可单选勾选 |
| 右：目录型菜单 | 显示说明条 + 下级菜单跳转 chip（目录本身无操作按钮）；说明条会点明"新增/编辑页不单列菜单，可访问性由下级操作权限控制" |
| 右：并入的操作项 | 带「来自 XXX」灰色来源标签，标明该操作属于哪个新增/编辑页 |
| 右：并入提示条 | 选中含并入子页的菜单时，顶部显示紫色提示条，列明并入了哪些子页面及其操作权限项数 |
| 右：纯展示页 | 空态「该菜单为纯展示页面，暂无可配置的操作按钮权限项」 |
| 右：全选 / 清空 | 仅作用于当前选中菜单的操作按钮 |
| 底部汇总 | 实时显示「已选 N 个菜单 · M 个操作按钮」 |

**保存校验**
- 角色名称、角色编码必填；编码格式与唯一性校验
- 至少勾选一项权限，否则拦截保存并提示

### 4.3 权限详情抽屉（只读）

- 角色基本信息 + 数据权限徽标 + 角色描述
- 权限概览：菜单权限 N 项 / 操作按钮 M 项
- 权限树：蓝色勾选 = 已授权，半选 = 部分授权，灰色 = 未授权
- 已授权操作按钮清单（chip 列表）
- 底部「编辑该角色」→ 关闭抽屉后直接打开编辑弹窗

### 4.4 通用交互

- `Esc` 关闭：确认弹窗 → 角色弹窗 → 抽屉（按层级从内到外）
- 所有保存 / 删除有 toast 反馈
- 角色数据存 `localStorage`（key `rp_roles_v1`），刷新不丢
- 内联 `onclick` 用到的方法必须挂到 `window`（否则 IIFE 内的函数在内联处理器里取不到）

## 5. 异常处理

| 场景 | 处理 |
|------|------|
| 角色名称为空 | 字段红框 + 「请输入角色名称」，保存拦截 |
| 角色编码为空 / 格式非法 | 字段红框 + 「请输入角色编码（仅支持字母、数字、下划线）」 |
| 角色编码重复 | 字段红框 + 「角色编码已存在：{角色名}」 |
| 未勾选任何权限 | toast「请至少勾选一项权限」，保存拦截 |
| 删除已关联用户的角色 | 确认弹窗提示「已关联的 N 名成员将变为无角色状态」，用户确认后仍执行删除 |
| 目标菜单无操作按钮 | 右侧显示空态说明，不报错 |
| 树搜索无匹配 | 左侧显示「没有匹配的菜单」空态 |

### 4.5 缓存与「部署即生效」

| 位置 | 策略 |
|---|---|
| nginx `css/js/html` | `no-cache, must-revalidate`（带 ETag 协商，未变更回 304） |
| nginx 图片 | `public, max-age=86400` |
| 权限树 js 的 script src | 自动带 `?v=<内容hash>`（生成器写入） |

> ⚠️ 曾经用 `max-age=604800`（7 天强缓存）导致**用户浏览器一直拿旧版权限树**，
> 而自动化验证因为每次用全新浏览器 profile（无缓存）测不出来 —— 是假绿。
> 现在有 `scripts/verify_cache_freshness.py`（持久化 profile）专门守这条。
