### 5.3 关键交互流程（v1.1 重要 + v1.7.99.31 扩展）

**步骤 0：v1.7.99.31「已完成准入企业」自动带入（优先级最高）**
- 用户在"企业名称"输入框输入文字时，**先**检查 mockInProgressCompanies（"执行中"状态企业库）
- 如果输入内容（含短词）匹配其中某家企业：
  - **直接自动填全部 17 字段**（不是 5 字段）：客户类别 / 工商信息 5 / 联系人 4 / 负责人 2 / 银行 2 / 简称
  - **弹窗提示**（绿色 modal）："✓ 此企业已完成项目准入"+ 流程状态"执行中"（绿色） + 系统已自动带入列表（17 项基础信息 + 企业风险报告 X 项绿 Y 项黄）
  - 弹窗底部"关闭提醒"按钮 → 关掉提示弹窗
  - 关闭后字段**不锁定**，用户可继续核对/修改
- 如果不匹配 mockInProgressCompanies → 走 v1.7.99.16 模糊匹配下拉项逻辑

**mockInProgressCompanies 数据**（v1.7.99.31）：
- 河南诚泽运输有限公司（上游 / 5 绿 3 黄 / 含 1 项失信记录 + 1 项行政处罚 + 1 项经营异常）
- 杞县广润贸易有限公司（上游 / 6 绿 2 黄 / 含 1 项行政处罚 + 1 项经营异常）
- 中原粮食集团有限公司（下游 / 8 绿全通过）

**步骤 1：模糊匹配**
- 用户在"企业名称"输入框输入文字
- 输入 ≥ 1 字符时，输入框下方弹出模糊匹配下拉列表
- 下拉项显示企业名 + 法人 + 信用代码
- 最多显示 5 条匹配结果
- 提示文案动态变化："找到 X 条匹配，点击下拉项自动带入工商信息" / "无匹配企业，请确认输入"

**步骤 2：用户点击下拉项**
- 用户点击某个匹配项
- **触发"天眼查"接口**（mock 异步 200ms 加载）
- 自动填充 5 个字段：法定代表人、注册地址、统一社会信用代码、经营期限（止）、成立日期
- 这 5 个字段变成**灰色禁用**状态（`disabled`）
- 字段右上角显示"天眼查"小标签（自动带入标识）
- 提示文案变为：`<span style="color: var(--color-success);">✓ 工商信息已从天眼查带入，请核对</span>`

**步骤 3：用户核对/修改**
- 用户可点击禁用的"自动带入"字段 → 仍可编辑（点击"修改"后启用）
- 自动带入的字段若与天眼查数据不一致，用户可手动修改覆盖
- 客户类别/联系人/负责人字段由用户继续填写

**步骤 4：确认添加**
- 点击"确认添加" → 弹窗关闭
- 新增的关联企业以 tag-card 形式展示在主表单
- 弹窗表单清空，准备下次添加

### 5.5 表单校验规则（v1.2 补全）

> 完整通用规则见 `docs/00-form-validation-rules.md`，本页是其在 4 步骤立项场景下的具体落地。

#### A. 校验时机（双层）

| 校验层 | 触发 | 范围 |
|---|---|---|
| 步骤内校验 | 点击「下一步」 | 只校验**当前步** |
| 终态校验 | 点击「提交」（第 4 步） | 校验**全部 4 步** + 跨步业务规则 |

#### B. 各步骤校验项

| 步骤 | 必填校验 | 字段格式校验 |
|---|---|---|
| 1. 项目信息录入 | 项目名称、**项目小组成员**（v1.7.99.26 必填）、货物品类 | 业务周期起始 ≤ 结束；项目小组成员至少 1 个 |
| 2. 企业风险报告 | 至少 1 个关联企业（关键跨步规则） | 统一信用代码 18 位；手机号 11 位 1 开头 |
| 3. 提交审批 | 审批人至少 1 个 | — |
| 4. 准入完成 | 复检全部 3 步 | — |

#### C. 跨步业务规则

- 关联企业**至少 1 个**（终态校验时强制）
- 关联企业客户类别不可重复（同一类别只允许 1 个）
- 审批人不能与项目创建人相同

#### D. 步骤内校验失败行为

```
当前步有必填未填或格式错:
  + 停留当前步（不前进）
  + 标红所有错误字段
  + 滚动到第一个错误字段（top 200px 内可见）
  + 顶部 Toast「请完成本步必填项」或「XX 字段格式不正确」
  + 不调后端
```

#### E. 终态校验失败行为

```
校验全部 4 步不通过:
  + 跳转**第一个出错的 step**（不是当前步）
  + 该 step 内标红错误字段
  + 顶部 Toast「第 N 步未完成，请检查」
  + 不调后端
```

#### F. 字段格式校验规则（关联企业弹窗场景）

| 字段 | 规则 |
|---|---|
| 企业名称 | 非空 + 模糊匹配天眼查返回 ≥ 1 条 |
| 统一社会信用代码 | 18 位，**自动带入后用户可改**，但改后必须通过 18 位 + 字母数字混合校验 |
| 联系电话 | 11 位数字 + 1 开头，**手机号格式** |
| 邮箱 | RFC 5322 邮箱格式 |
| 数字金额字段 | > 0，最多 2 位小数 |
| 日期字段 | 起始 ≤ 结束 |

校验触发：失焦（blur）时实时校验，错误立即红字 + 红框（不调后端，只前端校验）。

#### G. 返回保护

用户在**任意一步**有未保存内容时（`isDirty=true`），以下操作必须二次确认：

| 触发 | 行为 |
|---|---|
| 点击「保存草稿」之外的其他按钮（返回/上一步/取消） | 弹「当前编辑内容将丢失，确定离开？」 |
| 点击 sidemenu 切换菜单 | 同上 |
| 浏览器关闭 / 后退 | beforeunload 系统提示 |

> 注：「上一步」按钮**不**弹确认（用户主动回到上一步是正常操作，已填内容保留在 state）。

#### H. 提交行为

| 状态 | 行为 |
|---|---|
| 校验通过 + 提交中 | 按钮「提交中...」+ loading 图标 + 禁用重复点击 |
| 提交成功 | Toast「立项提交成功」+ 跳 `project-detail.html?code=...` |
| 业务错误（如编号冲突） | **保留用户输入** + Toast 错误 + 按钮恢复 |
| 网络异常 | Toast「网络异常，请重试」+ 按钮恢复 |

#### I. 关联企业弹窗内的校验（独立子表单）

- 弹窗打开时清空上次输入（`isDirty=false`）
- 客户类别 / 企业名称为空 → 「确认添加」按钮置灰
- 选择了企业（自动带入字段已填）→ 「确认添加」按钮亮起
- 关闭弹窗（× / 背景 / ESC）前如 `isDirty=true` → 弹「当前编辑内容将丢失，确定关闭？」
- 点击「确认添加」 → 主表单 tag-card 列表新增 + 弹窗关闭 + 弹窗 state 重置
