## 1. 业务定位

**新增线下追保函**是追保函管理（02.09）的**线下场景新建页**——业务人员（核心企业）在线下与客户签署纸质追保函后，**回系统登记**（含线下凭证上传 + 双方签字盖章信息）。

| 维度 | 线下追保函（本页）| 线上追保函（bond-letter-new）|
|------|---------------------|-------------------------------|
| 签署方式 | 线下纸质（双方签字盖章）| 线上电子签署 |
| 凭证 | 扫描件 PDF/纸质拍照 | 电子合同 |
| 业务流程 | 线下签署 → 系统登记 | 系统直接发起 → 在线签署 |

### 1.1 入口

| 入口 | URL | 说明 |
|------|------|------|
| 追保函列表 + 新增追保函按钮 → 下拉"新增线下追保函" | `./bond-letter-new-offline.html` | 主入口（v1.7.99.191 列表页按钮下拉）|

### 1.2 v1.7.99.191 关键改动

- 从 v1.0 单一"新增追保函"页拆为 **2 种类型**：
  - 线上追保函（bond-letter-new.html）
  - **线下追保函**（bond-letter-new-offline.html，本页）
- v1.7.99.191 列表页按钮下拉：点击"+ 新增追保函" → 下拉选"线上 / 线下"
- 线下场景**必须上传扫描件 + 填写双方签字盖章信息**

## 2. 字段规则

### 2.1 区块 1：基本信息（10 字段）

| 字段 | 类型 | 必填 | 校验 |
|------|------|------|------|
| 追保函编号 | input | 是 | 系统自动生成 |
| 关联合同 | modal | 是 | 必填；引用销售/采购合同 |
| 追保金额（元）| number | 是 | 必填；min=0 |
| 追保日期 | date | 是 | 必填；不能晚于当前日期 |
| 生效日期 | date | 是 | 必填；≥ 追保日期 |
| 失效日期 | date | 是 | 必填；> 生效日期 |
| 追保类型 | select | 是 | 线下追保函（默认锁定，不可改）|
| 关联客户 | select | 是 | 必填 |
| 关联业务线 | select | 否 | 选填 |
| 备注 | textarea | 否 | 选填 |

### 2.2 区块 2：线下凭证（v1.7.99.191 关键）

| 字段 | 类型 | 必填 | 校验 |
|------|------|------|------|
| **线下追保函扫描件** | upload | 是 | **必传**；jpg/jpeg/png/pdf；单文件 ≤ 100MB |
| 扫描件说明 | textarea | 否 | 选填 |
| 核心企业签字人 | input | 是 | 必填 |
| 核心企业盖章日期 | date | 是 | 必填 |
| 客户签字人 | input | 是 | 必填 |
| 客户盖章日期 | date | 是 | 必填 |

**v1.7.99.191 关键决策**：线下追保函**必须上传扫描件 + 双方签字盖章信息**——这是合规审计要求。

### 2.3 校验规则

| 场景 | 校验 |
|------|------|
| 失效日期 ≤ 生效日期 | 红字提示"失效日期必须大于生效日期" |
| 未上传扫描件 | 禁用提交按钮 + 红字提示 |
| 双方签字盖章信息不完整 | 红字提示缺哪个字段 |
| 追保金额 ≤ 0 | 红字提示"追保金额必须大于 0" |

## 3. 按钮交互

### 3.1 主操作按钮

| 按钮 | 位置 | 行为 |
|------|------|------|
| **提交** | 底部 | 二次确认 → 写入追保函 |
| **取消** | 底部 | 返回追保函列表 |

### 3.2 辅助按钮

| 按钮 | 位置 | 行为 |
|------|------|------|
| 选择合同 | 区块 1 | 弹合同列表 |
| 上传扫描件 | 区块 2 | 弹文件选择 |
| 删除扫描件 | 单附件右侧 | 二次确认 → 删除 |

### 3.3 二次确认弹窗

- **提交确认弹窗**：
  - 标题：提交确认
  - 内容：确认提交本次线下追保函登记？提交后系统将更新客户/合同的追保金额
  - 按钮：取消 / 确定
  - 成功后 toast："线下追保函登记成功"

## 4. 异常处理

| 场景 | 处理 |
|------|------|
| URL 参数异常 | 顶部红色 bar + 返回追保函列表 |
| 关联合同已作废 | 红字提示"该合同已作废，无法发起追保" |
| 未上传扫描件 | 禁用提交按钮 + 红字提示 |
| 双方签字盖章信息不完整 | 红字提示 |

## 5. 跨模块联动

### 5.1 与追保函列表（bond-letter）

- 提交成功 → 跳追保函列表
- 列表刷新该追保函记录（类型=线下追保函）

### 5.2 与保证金池（02.10）

- 追保函生效 → 保证金池"待追保"状态更新
- 追保函失效 → 保证金池触发预警

### 5.3 与客户管理（02.02）

- 追保函关联客户 → 客户"风险敞口" / "保证金账户" 更新

### 5.4 与线上追保函（bond-letter-new）

- 两种类型业务语义相同，**仅签署方式不同**
- 业务人员按实际场景选择对应类型
