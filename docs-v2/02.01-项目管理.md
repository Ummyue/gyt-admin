## 1. 功能描述与触发条件

### 1.1 功能描述

✅ **项目管理（立项）是港通供应链的「业务起点 + 客户准入入口」**。业务人员发起立项申请 → 关联上下游客户 → 每个客户做风险报告（天眼查 + 平台自建黑灰名单/假国央企库）→ **5 步骤页面 + 5 节点串行审批** → 准入完成。**客户管理是项目立项的子流程**——客户从风险报告沉淀到客户台账，不走独立审批。

✅ **源文档 v1.1 锁定的 12 条关键规则**（`02.01-项目管理-立项.md` §1.1；规则 4~8、12 已按 2026-10-21 业务方裁决改写）：

| # | 规则 |
|---|------|
| 1 | **创建项目时必关联客户**（每个客户必做尽调） |
| 2 | **客户变更 / 新增 / 删除**通过**客户管理模块**维护 |
| 3 | **新增客户必须与现有项目关联**（不能脱离项目独立存在客户） |
| 4 | **5 步骤页面**（✅ 2026-10-21 裁决 D3 / QA-018、D6 / QA-021）：步骤 1 项目信息录入 → 步骤 2 企业尽调报告 → 步骤 3 **贸易风控合规报告** → 步骤 4 提交审批（5 节点审批链在此）→ 步骤 5 准入完成 |
| 5 | **5 节点审批**：提交 → 一级业务 → 二级（风控部 → 财务部）→ 三级总经理 → 完成 |
| 6 | **串行审批**（✅ 2026-10-21 裁决 D12 / QA-029「仅提供串行审批流」，与总纲 D1 / QA-013 同口径）——节点 3 内**风控部 → 财务部逐级串行**，前一节点通过后自动流转至后一节点；**源文档「OR 会签（风控 + 财务任一通过即可）」表述一律作废** |
| 7 | **风险扫描更名为【企业风险扫描结果】**（✅ 2026-10-21 裁决 D4 / QA-019）：6 个 Tab = 贸易风险 / 主体风险 / 经营风险 / 司法风险 / 关系发现 / 关键人风险；**新增【贸易风控合规报告】**，含 6 项检查项（明细见 §1.3.1） |
| 8 | **客户关联关系不再单列 4 维度股权关系 Tab**（✅ 2026-10-21 裁决 D5 / QA-020）：股权 / 对外投资 / 疑似实控人 / 实控控股 4 个维度**并入【企业风险扫描结果】6 个 Tab 与【贸易风控合规报告】6 项检查项**中体现 |
| 9 | **v1.0 审批流实现 = 消息推送**（保底方案） |
| 10 | **v2.0 审批流实现 = OA 对接**（拓展方案，致远 A8 OA） |
| 11 | **2 小时 SLA 自动催办** |
| 12 | **3 级串行 + 加签** 审批架构（✅ 2026-10-21 裁决：源文档「3 级 + 会签 + 加签」中的**会签表述作废**，一律按串行） |

✅ **v1.7.99.x 追加的 13 类客户准入材料**（`02.01-项目管理-立项.md` §13.3，v1.7.99.298 定义，v1.7.99.307 改紧凑分组折叠布局，挂在「添加关联企业」弹窗内）：
