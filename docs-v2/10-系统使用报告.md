## 一、报告说明

### 1.1 报告目的

本报告用于说明大宗商品数字供应链平台投入使用后，平台各类用户在日常业务活动中的实际使用方式、单据流转路径、模块应用分布与协同关系，作为平台交付验收、上线推广与后续功能迭代的参考资料。

### 1.2 报告范围

本报告覆盖平台已上线并可实际操作的全部功能域，包括：

- **准入与风控前置**：项目立项、客户档案、黑名单管理
- **合同与业务线**：采购 / 销售 / 运输合同、补充协议、业务线关联
- **履约与货权流转**：收发货登记、收货确认、货权转移、仓储出入库
- **资金与票据**：付款、退款、回款、保证金、结算单、发票、追保函
- **风险监控**：盯市价格监控、预警中心
- **数据与协同**：数据中心、通知中心、账户中心

### 1.3 编制原则

1. 报告内容**全部来源于平台已实现的功能与已确认的业务流程**，不含设计设想与未落地内容；
2. 报告**不列举具体业务单据数量、金额、效率提升比例等运行统计指标**——此类数据应以系统运行报表为准，不在本文档中虚构；
3. 涉及多部门协作的部分，按平台已固化的**串行审批流**与**线下资金操作 + 系统内凭证登记**机制如实描述。

### 1.4 读者对象

平台业务、风控、财务、仓储各岗位人员，以及平台管理方与验收方。

## 二、平台概述

### 2.1 平台定位

大宗商品数字供应链平台是一套面向大宗商品贸易全链路的协同作业平台。平台以**单据流转为主线**，将准入、合同、履约、货权、资金、票据、风险监控七个环节纳入同一套数据与审批体系，使一笔业务的发起、审批、执行、确认与归档在同一系统内完成闭环。

平台采用 **Web 端**形态，适配 PC 浏览器访问，按 1440px 基准宽度设计大屏多列表对比作业场景。

### 2.2 平台解决的业务问题

| 业务问题 | 平台的处理方式 |
|---------|-------------|
| 业务单据分散在个人手里，进度靠口头同步 | 全部单据进系统，工作台按 10 类待办统一归集，任一岗位可随时看到自己负责的环节 |
| 同一笔业务在不同环节重复录入 | 客户、合同、业务线、物流、资金单据之间建立引用关系，上游单据信息沿链路带出 |
| 审批链走向不透明，事后难以追溯 | 审批统一为串行流程，每一节点在单据时间线上留痕 |
| 资金操作与系统记录脱节 | 实际付款在系统外完成，系统内完成**凭证上传与双方确认**，资金口径可追溯 |
| 风险信号发现晚、处置无闭环 | 风险扫描结果、盯市指标、预警规则形成统一信号入口，预警按处置流程跟踪 |
| 管理层看不到全局 | 数据中心按业务线、合同、资金、库存、合规口径汇总 |

### 2.4 平台运行原则

- **审批流统一为串行**：所有含审批的环节按节点逐级流转，任一节点驳回即终止本单据。
- **资金操作线下完成**：实际付款 / 收款通过银行等渠道完成，平台承担凭证登记与双方确认职责，不执行线上扣款。
- **文档单一可信**：项目准入完成后可导出整体报告（PDF），作为项目全过程的书面归档。
- **风险信息分层展示**：企业信用代码与联系电话默认脱敏展示，需要时可手动查看完整信息，查看行为留痕。
- **仅 Web 端交付**：本期不提供移动端应用，仓储现场作业同样在浏览器中完成。

## 四、分角色使用情况

### 4.1 业务员

**职责定位**：业务链条的发起者与单据录入者，负责把线下商务动作转成系统内可流转的单据。

**主要使用模块**：项目管理、合同管理、业务线管理、收发货管理、货转管理、资金管理、工作台。

**典型作业路径**

1. **发起项目立项**：在工作台进入新增立项申请，按 5 个步骤依次完成——项目信息录入 → 企业尽调报告 → 贸易风控合规报告 → 提交审批 → 准入完成。系统自动调取企业工商、司法、经营等多维数据生成尽调报告与合规报告，步骤 3 顶部同步展示预计完成时间等关键指标。
2. **沉淀客户档案**：尽调通过的项目自动沉淀为客户档案，避免重复建档。客户按上游供应商、下游客户、第三方物流企业、第三方仓储企业四类归口。
3. **签订合同**：在合同管理中新建采购或销售合同，支持框架合同与单批次合同两种形态，录入合同要素后进入审批。
4. **关联业务线**：合同签订后关联业务线，将合同项下的货物与资金台账绑定到同一条业务线上。
5. **录入发货与收货**：在收发货管理中登记发货，同一张发货单既承载上游发货也承载下游收货，具体收哪一端取决于发货登记时的方向标识。
6. **发起货权转移**：在货转管理中发起货转申请，货转单状态在审批中、待上传已生效单据、已生效、驳回、已作废五个业务状态之间流转。
7. **发起付款申请**：在资金管理中发起付款，线下完成转账后回平台上传凭证。

**系统提供的支撑**

- 立项 5 步表单采用分步校验，步骤之间数据自动带出，减少重复录入；
- 风险扫描结果以统一的风险维度呈现，便于快速判断对手方风险；
- 收发货、货转的单据支持附件上传与凭证留存，业务留痕完整；
- 工作台待办按 10 类归集，业务员打开系统即可知道"今天该我推进哪几笔"。

**使用价值**：单据一次录入、全链路复用；业务进度在系统内可视，减少跨部门口头问询与重复登记。

---

### 4.2 业务主管 / 业务负责人

**职责定位**：业务部内部的审批把关人与进度统筹者。

**主要使用模块**：工作台、各业务模块的审批节点、业务线管理、合同管理。

**典型作业路径**

1. **在待办中定位待审单据**：工作台"上下游合同审批""货转待审批""待付款审批"等 Tab 集中呈现待处理事项，按业务类型与状态筛选。
2. **审阅后逐级流转**：合同审批链最多支持 7 级串行节点，主管在本人节点处理后单据自动流转至下一节点。
3. **驳回并说明原因**：对信息不完整或条款不合适的单据选择驳回并填写意见，单据流程随即终止并回到发起人。
4. **查看业务线进度**：在业务线管理中查看本部门业务线的执行与完结情况，核对合同、货量、付款、结算、发票等指标。
5. **关注异常与作废情况**：对已作废的收货单据、已驳回的货转单据进行原因复盘。

**系统提供的支撑**

- 审批链以串行方式运行，节点顺序明确，主管不需要判断"该谁审"；
- 每一次通过、驳回都进入单据时间线，事后可完整回溯；
- 业务线详情页集中呈现 5 项关键指标，避免跨模块拼接数据。

**使用价值**：审批责任清晰、过程留痕；团队待办集中一处，审批节奏可控。

---

### 4.3 风控人员

**职责定位**：业务风险的识别、复核与处置责任人。

**主要使用模块**：客户准入、盯市价格管理、保证金管理、追保函管理、预警中心、工作台。

**典型作业路径**

1. **复核风险扫描结果**：在客户详情页查看企业风险扫描结果，风险维度覆盖贸易风险、主体风险、经营风险、司法风险、关系发现、关键人风险六个方面，并可查看贸易风控合规报告。
2. **人工复核高风险客户**：对系统判定为高风险或尽调未通过的客户，风控人员在客户准入环节进行人工复核，形成放行或终止结论。
3. **维护盯市价格指标**：在盯市价格管理中配置监控指标，配置项包括业务类型、指标名称、是否关联合同、规则类型、风险等级、考核项、配置阈值与消息类型；系统按配置实时监控价格波动。
4. **参与合同与项目审批**：在合同的串行审批链中承担风控节点，对交易对手与条款风险把关。
5. **处理预警信号**：在预警中心接收预警信号，预警来源覆盖工商变更、司法诉讼、经营风险与价格波动；按预警类型逐条研判并推进处置。
6. **维护黑名单与假央企国企库**：在黑名单管理中登记与解除名单，名单供尽调环节调用；黑名单命中以风险提示形式呈现，由业务人员自行判断后续动作。
7. **管理保证金与追保函**：调整保证金规模、登记追保函，跟踪敞口与担保有效性。

**系统提供的支撑**

- 风险数据一次性归集，工商、司法、经营多源信息在客户详情页统一呈现；
- 盯市指标的阈值、风险等级、消息类型可配置，监控规则随业务调整；
- 预警信号按类型分列，处置动作与结果在系统内跟踪，形成闭环；
- 黑名单与假国央企库由平台自建维护，在尽调环节即时生效。

**使用价值**：风险识别从分散查询转为集中复核；预警从被动等待转为按规则主动推送，处置过程有据可查。

### 4.4 财务人员

**职责定位**：资金与票据的账务处理者，负责单据金额与凭证的一致性。

**主要使用模块**：资金管理、保证金管理、结算单管理、发票管理。

**典型作业路径**

1. **审核付款申请**：接收业务发起的付款申请，核对合同、金额与收款方信息后完成审核。
2. **线下转账并回传凭证**：实际资金划转通过银行渠道完成，财务人员在系统中上传付款凭证。
3. **确认到账**：收款方在系统内完成到账确认，单据状态随之推进；双方确认环节由系统记录。
4. **发起退款与回款登记**：按业务需要处理退款，并在回款登记中录入实际回款信息。
5. **登记与调整保证金**：在资金管理下的保证金子模块中登记保证金、发起追加 / 冲抵 / 退款三类调整，并查看调整记录。
6. **发起结算单**：在合同项下发起结算单，关联对应业务线与货物明细，提交财务审核。
7. **开具与核对发票**：在发票管理中处理进项 / 销项发票，跟踪发票状态与红冲、作废等操作。

**系统提供的支撑**

- 资金链路的"发起—凭证—确认"三段式结构，保证系统记录与实际资金流一一对应；
- 结算单与合同、业务线、货量关联，金额口径可回溯到源单据；
- 发票状态与合同、业务线、结算单联动，跟踪链条完整；
- 保证金的三类调整方式与调整记录独立留痕，余额变动可查。

**使用价值**：资金单据与业务单据同源，金额核对不必跨系统比对；凭证与确认动作在系统内留痕，账务处理有据可依。

---

### 4.5 总经办

**职责定位**：高风险事项的最终决策节点。

**主要使用模块**：各业务模块的终审节点、工作台。

**典型作业路径**

1. **从工作台接收终审待办**：需要终审的事项进入待办列表，与常规审批事项一并呈现。
2. **调阅前序材料**：在单据详情页查看项目信息、尽调与合规报告、合同条款、关联业务线及前序节点意见。
3. **终审决策**：通过则流程结束、单据进入执行态；驳回则流程终止并说明决策依据。

**系统提供的支撑**

- 终审节点与常规审批在同一套串行流程中，位置清晰；
- 详情页按区块组织前序信息，减少为决策额外查询；
- 决策意见进入单据时间线，责任可追溯。

**使用价值**：关键决策材料集中呈现，决策过程规范留痕。

---

### 4.6 仓储作业人员（库管员 / 仓储员 / 库管负责人）

**职责定位**：货物实物出入库与放货作业的执行方。

**主要使用模块**：仓储管理、收发货管理、货转管理。

**典型作业路径**

1. **入库登记**：在仓储管理中登记入库，录入货物信息、仓房货位与相关单据。
2. **出库与提货管理**：按提货指令办理出库，登记出库明细与数量。
3. **放货执行**：接收放货指令并执行放货，填写执行记录。
4. **库存台账维护**：查看库存台账与库存数量、重量、预占量等指标，核对实物与账面。
5. **巡库记录**：按周期登记巡库结果，巡库记录留存可查。
6. **配合收货确认**：在收发货管理中完成发货登记与收货确认，货物流转节点即时同步。
7. **配合货权转移**：在货转环节上传已生效单据，货权状态随之更新。

**系统提供的支撑**

- 入库、出库、提货、放货四类作业各有独立的操作页与状态流，作业边界清晰；
- 库存台账以关键指标 + 明细列表双 Tab 呈现，核对效率高；
- 仓房、货位、库点、站点分层建模，实物位置可精确到货位；
- 作业全部在浏览器中完成，现场无需额外终端。

**使用价值**：实物作业与系统台账同步更新，减少事后补录；放货与货转节点衔接紧���，货权与实物对应关系清晰。

## 五、跨角色协同场景

### 5.1 一笔业务的全链路流转

平台以**单据流转**为主线，各岗位在同一笔业务上接力。以一笔采购业务为例：

```
① 准入 · 风控前置
   业务员发起立项 → 系统调取企业多维数据完成尽调与合规扫描
   → 通过则沉淀为客户档案；未通过转风控人工复核

② 合同 · 业务线
   业务员签订合同 → 业务部 + 风控部串行审批 → 关联业务线，锁定货物与资金台账

③ 履约 · 货权流转
   业务员录入发货 → 货主方收货确认
   → 发起货转完成货权转移 → 仓储出入库登记与放货执行

④ 结算 · 资金闭环
   业务员发起结算单 → 财务审核 → 线下转账 → 发起方上传凭证 → 收款方系统内确认
```

### 5.2 典型协同关系

| 协同对 | 协同内容 | 平台承载方式 |
|-------|---------|-------------|
| 业务员 ↔ 业务主管 | 合同、货转、付款单据审批 | 串行审批链 + 工作台待办 |
| 业务员 ↔ 风控人员 | 尽调结果复核、高风险放行 | 客户准入复核 + 合同风控节点 |
| 业务员 ↔ 财务人员 | 付款、结算、发票处理 | 资金单据 + 凭证上传 + 双方确认 |
| 业务员 ↔ 仓储人员 | 发货、收货、放货执行 | 收发货单据 + 仓储作业页 |
| 仓储人员 ↔ 风控人员 | 货权转移与已生效单据 | 货转单据 + 附件上传 |
| 风控人员 ↔ 财务人员 | 保证金、追保函与资金占用 | 保证金子模块 + 追保函 + 资金台账 |
| 各岗位 ↔ 管理层 | 业务与资金全景掌握 | 数据中心（驾驶舱 + 台账报表 + 合规验证） |

### 5.3 资金与票据的协同规范

平台对资金类动作采用统一的三段式处理，各岗位在其中的职责是：

| 环节 | 执行方 | 平台记录内容 |
|------|-------|-------------|
| 实际划转 | 线下通过银行等渠道完成 | — |
| 凭证登记 | 发起方上传付款凭证 | 凭证附件、金额、关联单据 |
| 双方确认 | 收款方在系统内确认 | 确认动作、确认时间 |

该规范保证资金动作在系统内**有凭证、有确认、有时间点**，同时平台不承担代付职能。

## 七、使用规范与注意事项

### 7.1 通用操作规范

1. **单据提交前的必填校验**：平台在提交环节对必填项、格式与业务规则做统一校验，校验不通过的单据无法进入下一环节；
2. **离开页面前的返回保护**：表单存在未保存修改时切换页面会触发提示，避免录入内容丢失；
3. **提交失败保留输入**：提交失败时已填写内容保留，便于修正后再次提交；
4. **危险操作二次确认**：作废、删除、批量导入等操作均有明确确认弹窗；
5. **凭证附件规范**：业务凭证附件支持上传并留存，单个附件大小上限 100MB。

### 7.2 各岗位注意事项

| 角色 | 注意事项 |
|------|---------|
| 业务员 | 合同类单据需在签署后上传双签合同，单据方可进入执行态；发货登记时务必确认方向，方向决定后续是上游发货还是下游收货 |
| 业务主管 | 驳回时填写具体意见，便于发起人一次修改到位；涉及作废的单据需在流程外做好业务交接 |
| 风控人员 | 黑名单命中在系统中为提示性质，建议结合业务实际判断；盯市指标调整后关注新预警的产生情况 |
| 财务人员 | 资金动作须在系统内完成凭证上传与双方确认，勿以线下沟通替代；结算与发票金额需与合同、业务线口径核对一致 |
| 总经办 | 终审通过后单据直接进入执行态，请在放行前确认前序节点材料完整 |
| 仓储人员 | 仓库、仓房、货位按层级选择，避免录错导致实物与台账不符；放货执行后及时回填执行记录 |
| 管理员 | 账户信息变更后通知相关使用人员；企业信息维护后建议在客户档案中同步核对 |

### 7.3 数据安全与隐私

- 平台的**交付文档**对手机号、统一社会信用代码等敏感字段做脱敏处理；
- 平台**运行界面**默认以脱敏状态展示企业信用代码与联系电话，需要时可手动查看完整信息，查看行为被记录留痕；
- 登录账号与个人信息由账户中心统一管理。

## 八、结语

大宗商品数字供应链平台以单据流转为主线，把准入、合同、履约、货权、资金、票据与风险监控七个环节纳入同一套作业体系。平台上线后，业务、风控、财务、仓储各岗位在同一套数据与流程上协作：业务侧的单据一次录入、全链路复用；风控侧的风险识别与预警处置形成闭环；财务侧的资金凭证与双方确认可追溯；仓储侧的实物作业与系统台账同步更新；管理层通过数据中心掌握业务与资金全景。

平台后续将结合各岗位的实际使用反馈，持续优化作业路径与信息呈现效率。
