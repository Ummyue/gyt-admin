## 一、这是什么

把原 `docs/` 目录中按**技术实体维度**组织（表结构 / 状态机 / 字段规则）的 18 份模块与规范文档，重组为按 **PRD Writer 范式**组织（产品定位 → 用户动线 → 带优先级功能清单 → 交互状态 → 数据规范 → 文案 → 非功能需求 → 待确认）的需求文档树。

| | 原 `../docs/` | 本目录 `docs-v2/` |
|---|---------------|------------------|
| **组织维度** | 技术实体（表 / 状态机 / 字段） | 用户价值（动线 / 优先级 / 交互状态） |
| **文件数** | 18 份模块/规范 + 112 份页面级 PRD | **18 份范式化文档**（页面级 PRD 仍指向 `../docs/`） |
| **状态机** | 与其它章节平铺 | 归入范式「§3 状态清单」并补 UI 6 态 |
| **异常处理** | 独立章节 | 归入「§4 边界条件」+「文案规范」 |
| **版本矛盾** | v1.0 与 v1.7.99.x 互相冲突，静默并存 | **逐条标 ⚠️ 并列，不选边**，收拢到 §3.4 + §7 |
| **信息缺口** | 隐含 | 显式标 [待补充]，**不编造** |

### 信息溯源标记（全文通用）

|------|------|

### v2.1 业务方裁决（优先级高于源文档全部历史版本）

| 编号 | 裁决项 | 结论 | 证据 |
|------|-------|------|------|
| **D1** | 合同签署状态术语 | **单签 = 界面「待盖章」；双签 = 界面「已双签」**——同一组状态的两种叫法 | ✅ 线上录屏实证：附件必传项「待盖章合同附件」+ 操作按钮「上传双签章合同」 |
